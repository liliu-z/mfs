# Concurrency, recovery, and StashBase review: 2026-09-12

**Historical record; the library findings below were subsequently fixed.** The current contract is [design.md](design.md), and implementation checkpoints are in [backlog.md](backlog.md). This report preserves pre-fix triggers, evidence, and reasoning; source locations refer to the reviewed baseline.

MFS baseline: `a872bde037c55041d9adb20ebed2ea9952c96f00`, including working-tree changes. StashBase baseline: `7c146e1c1aa1e017f45695ab49dd6f34136d9ee9`, also reviewed with its working-tree changes. Existing StashBase changes were not modified. The review found seven implementation defects and two missing host contracts: temporary source retirement and migration of user intent. The later implementation addressed all nine library concerns; StashBase migration remained separate.

## Evidence and scope

The review covered Lifecycle/Worker, observation, preparation, indexing, retrieval, file references, GC, and the host's daemon/conversion/file-operation/migration paths. Baseline `.venv/bin/python -m pytest -q` reported **119 passed, 3 skipped, 7 warnings in 274.95 seconds**. Skips required native Windows handles; warnings came from PDF/SWIG dependencies.

Temporary scripts used real SQLite/Milvus in disposable directories and deterministic fault/interleaving injection. The process probe used actual `ProcessingContext.run_process` and host SIGKILL. Original `/tmp` script paths below are provenance, not retained checkout files. Maintained regressions were added during the subsequent implementation. Real OCR/cloud embedding quality, throughput, and migrated application flows were not tested.

## Confirmed implementation findings

### 1. P1: a lost delete acknowledgement could resurrect a durable deletion

At baseline `Lifecycle.remove` (lines 661-665 in [_lifecycle.py](../src/mfs/_lifecycle.py)) committed SQLite before updating memory/visibility. A post-commit exception did not reconcile persistent state as acceptance/persistence paths did.

The probe blocked a Processor, committed deletion, injected one `StorageFailed`, then released the old Processor. SQLite first held a delete target, but the stale permit overwrote it with upsert and read/search returned deleted content. A completed-document variant produced durable delete/pending versus memory upsert/succeeded, with stale search hits and an immediately successful wait.

The fix needed one transaction/reconciliation path for remove, drop, rules, cancellation/retry, configuration, and rebuild. If the outcome cannot be read back, stop stale publication rather than trust memory. Evidence: `/tmp/mfs_review_lost_remove_resurrect.py` and `/tmp/mfs_review_lifecycle.py`. These were injected failures, not a naturally occurring disk incident.

### 2. P1: a source change during extraction polluted the content cache

At baseline `Preparation.prepare` (lines 73-81, 131-141, 196-198 in [_preparation.py](../src/mfs/_preparation.py)), source hash validation happened before calling Processor but not again before caching results.

The deterministic sequence accepted alpha, changed the External source to bravo during processing, and cached `extracted bravo` under alpha's hash. After syncing bravo, restoring alpha, and syncing again, processing was skipped and the wrong text remained searchable. Evidence from `/tmp/mfs_review_source_race.py`: `restored source alpha mfs text extracted bravo calls 2`; real BM25 still found bravo.

This exceeded ordinary between-sync staleness: the final source was stable and resynced. The correction needed identity/hash/change-metadata checks around results and checkpoints, including change-and-restore cases. Adapters requiring stronger input semantics still need stable reads; zero-copy is not snapshot isolation.

### 3. P1: managed POSIX children survived host SIGKILL

Baseline `run_process`/`ProcessTree.close` relied on the parent's `finally` to kill an independent process group. SIGKILL bypassed that cleanup. The actual probe recorded `host_exit_code=-9`, `managed_child_alive_after_host_sigkill=true`, and `child_wrote_after_parent_death=true`; the probe cleaned up afterward.

The host already had EOF/SIGTERM/SIGKILL escalation in `server/mfs-daemon.ts`. Surviving OCR/transcription could therefore overlap reopened work, retain source handles/resources, and write into old work directories whose pins were lost. This overlap was an inference from the demonstrated surviving child, not an observed production incident.

The fix required supervision surviving daemon death, actual descendant retirement before new instance recovery, and PID-reuse-safe ownership. Windows already used a Job Object; its native behavior was not tested on this machine.

### 4. P1: cancelled files retained obsolete index stages across rebuild

Baseline `Lifecycle.finish_rebuild` skipped cancelled targets after clearing the collection, preserving their old stage, plan, and completed batches. The sequence pause-before-publish, cancel, reindex, retry left `cancelled publish rows=0`, then repeatedly failed with `publication is missing chunk rows`. An interrupted embed could similarly retain batches that no longer existed.

The fix retained user cancellation and compatible process checkpoints while resetting prepared files to chunk and clearing obsolete index plans/batches. Evidence: `/tmp/mfs_review_cancel_reindex.py`.

### 5. P2: strong search waited indefinitely on known terminal failures

Baseline `ReadView.wait_ready` only waited for pending work to disappear, although failed/blocked/cancelled targets remained in that set. After a permanent Processor failure, ordinary wait immediately raised `OperationFailed`, while strong search with 0.15 seconds took about 0.154 seconds and raised only `WaitTimeout`. Without a deadline it could wait indefinitely; four such waits could occupy the query pool.

The fix shared terminal-failure evaluation with current-work wait while preserving revision/error information. Evidence: `/tmp/mfs_review_lifecycle.py`. Pauses and binding dependencies also needed explicit waiting semantics.

### 6. P2: a work-directory grep output was accepted as borrowed, then collected

Baseline preparation copied work-directory `text_path` into owned storage but always marked `grep_path` borrowed. A Processor returning `context.work_dir / 'grep.txt'` initially read successfully; after GC it raised `SourceUnavailable`.

The fix unified text/grep ownership handling, copying temporary grep outputs into managed storage with persistent references and cache integrity checks. Truly external borrowed outputs remain host-owned. Evidence: the second part of `/tmp/mfs_review_scan_gc.py`.

### 7. P2: an unreadable subtree prevented confirmed deletions elsewhere

The scan's missing-file inference depended on overall `complete`. After indexing `gone.txt` and `denied/keep.txt`, the probe deleted the former and injected PermissionError only for the latter subtree. Root enumeration proved `gone.txt` absent, yet no removal was reported and its ranked result remained.

The fix tracked successful coverage and failed prefixes independently, preserving only uncertain regions. An inaccessible whole root still cannot mean an empty directory. Evidence: the first part of `/tmp/mfs_review_scan_gc.py`.

## Missing host contracts identified at the time

**Temporary retirement before source operations.** Existing host file guards retired conversion/source handles before rename/move/delete. MFS `cancel` persisted user intent and ordinary wait failed on cancellation; polling `executing` alone could not prevent another claim. Combining these ad hoc risked turning a temporary operation into permanent cancellation.

The required sequence was host path lock, temporary scope admission gate, actual execution/source-read retirement, disk operation or compensation, sync of old/new ranges, then independent lease release. All namespaces sharing a physical source and host playback/viewer users had to be included. This became `quiesce`/`ScopeLease`.

**Importing existing user intent.** A plain full sync into a new namespace would restart previously cancelled/failed expensive work. MFS legacy catalog migration was not an importer for StashBase's database. The host needed a replayable migration log and a preparation admission gate while restoring IDs, rules, settings, and file state. Index pause alone did not stop Processor. This became persistent `processing_paused` and revision-checked `restore_document_state` on the library side.

## Integration recommendations at this checkpoint

Use one existing Python daemon and one External namespace per persistent Folder ID. MFS owns preparation/checkpoint/index/recovery targets; StashBase owns source operations, playback, product policy, Viewer, and Library-wide presentation. Map old manual Sync/MCP reindex primarily to source observation; explicitly retry failed targets. Preserve keyword grep/fallback and map semantic intent to hybrid. Supply JSON/HTML processors explicitly; built-in UTF-8 only routes TXT/Markdown. Separate source limits from the recorded 8 MiB index-text policy.

At this checkpoint MFS had one file worker, while StashBase used two light and one heavy lane. Cooperative checkpoints alone did not restore parallel throughput. Bounded multi-worker execution with resource admission was a proposed next step and was later implemented. Host-prepared-output notification remained an alternative requiring durable incarnation/revision-scoped wakeups and retention, not unconditional retry.

Long wait/reindex calls needed responsive request dispatch. The recorded host was then serial; later dispatcher fixes are documented in [the liveness review](review-2026-09-13-liveness.md). Packaging needed Python 3.13, replacement of old private imports, and a frozen supervisor entry point. These historical recommendations do not establish current host implementation status.

## Subsequent library implementation

| Finding | Implemented correction |
| --- | --- |
| Lost state-command acknowledgement | Unified transaction reconciliation and stale-permit invalidation; stop scheduling/publication when reconciliation fails |
| Changed source in cache/checkpoint | Source hash/identity/change-metadata guard, prepared-text hash checks, processing-cache format update |
| Orphaned POSIX execution | Separate supervisor with inherited ownership through process-group retirement; frozen entry dispatch |
| Cancel/reindex/retry | Preserve cancellation, reset obsolete index plan and batches to chunk |
| Strong terminal wait | Shared terminal-state handling with current work wait |
| Temporary grep reference | Managed copy with durable references and cache validation |
| Partial scan isolation | Missing inference by successful coverage and failed prefixes |
| Source-operation retirement | Incarnation/path ScopeLease covering execution and source reads, overlap, timeout, late reads, and recreation |
| User-state migration | Persistent preparation pause and revision-checked replay-safe failed/cancelled import |

Formal regressions are in [test_audit_regressions.py](../tests/test_audit_regressions.py) and [test_quiescence.py](../tests/test_quiescence.py), including real host SIGKILL and deterministic state/source interleavings. The subsequent implementation recorded **146 passed, 3 skipped**; see [backlog](backlog.md) for exact checkpoints.

Zero-copy still provides no atomic external snapshot. Host operations and sync require serialization/all relevant scopes; managed POSIX commands cannot escape their session. Native Windows and actual frozen application acceptance remained environment-specific. The single-worker limitation at this checkpoint was subsequently superseded, while host completion notification was not implemented.
