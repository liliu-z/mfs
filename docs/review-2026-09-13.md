# Implementation and StashBase review: 2026-09-13

**Historical pre-fix evidence.** R1-R8 were subsequently fixed and converted to maintained regressions in [test_review_boundaries.py](../tests/test_review_boundaries.py). Follow-ups added recoverable candidate maintenance, same-configuration retry, lost member-commit acknowledgement handling, capped background aging, and separate grep/ranked-query capacity. The [independent review](review-2026-09-13-independent.md) identified and verified four further fixes. See [design.md](design.md) for the current contract.

The review examined MFS `a872bde` plus all working-tree changes and a clean StashBase `7c146e1`. It initially added only this report and [the reproduction script](review-2026-09-13-repro.py), without modifying implementations. The conclusion at that checkpoint was that responsibility separation was sound but search omissions, stuck configuration, and unsafe source reads prevented direct application replacement.

The scope included acceptance, targets/actual execution, configuration generations, retrieval, observation, preparation, cleanup/GC, managed subprocesses, and host daemon/search/conversion/playback/file transactions. Source line numbers below refer to the historical baseline, not the current files.

## Reproduced implementation findings

### R1 / P1: stale-snapshot deduplication hid current search results

Baseline [_index.py](../src/mfs/_index.py) line 519 deduplicated by `(namespace, doc_id, ordinal)` before [_reader.py](../src/mfs/_reader.py) line 382 filtered eligibility. It omitted `snapshot_id`. A higher-scoring old row could replace the current row during deduplication, then be removed by visibility filtering, leaving nothing.

A real-Milvus probe updated `old needle` to `new needle`, delayed only old-snapshot cleanup, waited for the new index, and queried vectors. The backend held both rows and `indexed_revision == revision`, yet returned `SearchResult(items=(), truncated=False)`. Cleanup can legitimately be delayed by old query leases, so this was not merely an artificial failure state.

The fix preserved snapshot identity through visibility filtering. Candidate saturation by stale rows also needed bounded expansion and truthful truncation rather than claiming a complete empty answer.

### R2 / P1: old adapter binding could overwrite a newly promoted model

Baseline `open_namespace` read G0, built/verified its binding, then took the lifecycle lock to install it without rechecking generation. Maintenance could promote G1 in between because it did not share the facade mutation lock.

The probe paused a validated G0 bind, completed/promoted G1, then resumed G0 installation. Binding returned successfully but vector queries continually raised `NamespaceCompatibilityError`: active configuration was G1 while the runtime object was G0.

The correction atomically revalidated incarnation, generation, and manifest before adopting either active or candidate bindings. It did not move slow model loading under the global state lock. Baseline locations: `_core.py` lines 640/670 and `_configuration.py` line 330.

### R3 / P1: candidate membership failure was unrecoverable by the same request

Configuration persisted the candidate before synchronously generating per-file build targets. If a member write failed, repeating the same manifest returned `changed=False`; maintenance initialized/promoted but never repaired missing membership.

One injected `StorageFailed` on the first candidate target write left an initialized collection and empty `build_targets`; normal storage recovered, but repeated configuration still timed out. Reopen reconstructed members, proving a recovery source existed without a same-process recovery loop.

The correction made declaration separate from bounded, idempotent background membership reconciliation. It also shortened configuration admission: the pre-fix 3,000-file processing-paused fixture took about **0.525 seconds** for configuration and blocked concurrent status for **0.499 seconds**, without conversion or embedding. This measured one synthetic scale, not general production latency. Baseline `_configuration.py` locations: lines 49, 99, 208.

### R4 / P1: grep's timeout did not bound execution

The timeout was only passed to strong text readiness. Eventual scanning, source mapping, and Chunker/admission waits had no shared deadline. Source mapping rescanned every span for each hit.

A **140 KB / 20,000-line** UTF-8 file with 5,000 matches and `timeout=0.01` took about **2.9 seconds**. A blocked Chunker under `select="chunk"` also waited beyond timeout until explicitly released. Byte/match budgets did not bound execution time.

The fix added total grep deadline/execution capacity, deadline checks at stages and admission, and ordered-span source lookup. Baseline locations: `_reader.py` lines 186/258, `_documents.py` line 43, `_runtime.py` line 176. The host's then-existing cancellable ripgrep behavior could not be assumed equivalent before this correction.

### R5 / P1: post-sync symlink replacement exposed unrelated text

Observation safely opened source files, but later grep/read used ordinary path opens. After sync, replacing `root/a.txt` with a symlink to a file outside the root made grep/read expose that file under the original DocumentId.

The correction reused safe regular-file/no-follow opens and source-read eligibility checks at actual read time. An explicitly borrowed derived file outside the root remains legitimate; a blanket root-only rule would incorrectly reject it. The probe demonstrated an MFS issue, not an equivalent defect in the old StashBase implementation. Baseline locations: `_reader.py` line 155, `_artifacts.py` line 131, `_lifecycle.py` line 1633.

### R6 / P2: one unreadable External source failed an entire grep

Two accepted files contained the query; deleting the first without sync caused `SourceUnavailable` before the healthy file's hit could return. File changes between scans are part of normal host behavior.

The fix returned healthy hits plus structured per-file `failures` and `truncated=True`, including temporary quiescence. Known-document read could still raise directly. Invalid queries/storage corruption must not be swallowed as empty results. Baseline `_reader.py` locations: lines 225/159.

### R7 / P2: expired backend-lock waiters still launched backend work

The baseline shared one backend lock across collections and computed remaining time before waiting on it. After a caller timed out, releasing another call's lock still launched the obsolete search with its stale budget.

Caller timeout worked, but unnecessary backend execution retained query capacity/collection leases and delayed valid work and shutdown. The fix included lock acquisition and post-acquisition validation in the same deadline. The inability to interrupt an already running native call should not apply to work that has not started. Later maintenance work further changed lock scope and handler-retirement semantics. Baseline `_index.py` locations: lines 92/476.

### R8 / P2: normal SQLite contention was reported as GC storage failure

GC used zero busy timeout to defer to normal work but classified SQLITE_BUSY/LOCKED as `StorageFailed` rather than `busy=True`. Worker artifact registration could write outside the lifecycle lock.

The full run failed `test_staged_internal_request_cannot_overwrite_later_intent[update]` with `catalog transaction failed: database is locked`; isolated rerun of both variants passed. A held write transaction reproduced `busy=False, error=StorageFailed(...)` deterministically. No data loss was observed.

The fix classified only normal busy/locked contention as retryable GC busy, preserving corruption/I/O failures. An isolated pass was not proof the race had gone. Baseline `_artifacts.py` locations: lines 285/372.

## Additional design and host work at this checkpoint

Candidate initialization could exhaust its five-failure budget without an actionable same-configuration retry path. Namespace diagnostics needed maintenance errors and pending status, not just file errors. Subsequent fixes supplied batched recovery, diagnostics, and same-manifest retry.

Background priority used unbounded `base_priority - age`, allowing an old background task above new interactive work; the host contract capped aging at active-folder. This code-level policy difference was fixed; it was not a measured real-corpus latency claim. At this checkpoint Embedder shared object admission with background work; later EMBED-006 removed those gates. Current limits are described in the design, not this historical observation.

Host playback handoff, task identity, optional shared grants, actual retirement after RPC timeout, and local-model/provider limits needed explicit integration. Close correctly waited for real calls and could not force-stop arbitrary Python/native work; the host required bounded escalation/restart. A Processor waiting for Node while Node waited for it could still create a cross-process cycle without an independent control path.

Use one daemon and stable External namespace per Folder. The host retains source/member authorization, disk transactions, Viewer/playback, and global result presentation. Key acceptance needs were:

- Supply actual JSON/HTML/PDF/OCR/DOCX/transcription processors and source locations; preserve valid empty OCR completion and original identity.
- Preserve grep fallback, byte/renderer conversion, case/whole-word behavior, snippets, and product match budgets.
- Fan out Library/MCP queries under one deadline with per-Folder failures, overlap deduplication, and evaluated ranking; independent collection scores are not a global scale.
- Quiesce all source users before host disk operations, content-sync old/new ranges inside leases, and wait afterward. Later embedding failure must not blindly roll back an accepted rename.
- Retain shared outputs until all Folder/Viewer users retire; dropping parent membership is not physical source deletion.
- Import old failure/cancellation under processing pause and recover host path journals under startup pause.
- Rebind same-space credential changes; build candidates for model changes, preserving generation-specific query bindings.
- Replace old private imports, require Python 3.13, and validate actual frozen supervisor/native Windows behavior.

The host dispatcher was serial at this review's baseline, with a ten-minute Node timeout. Later [liveness work](review-2026-09-13-liveness.md) changed it to bounded dispatch/error propagation; [the boundary audit](review-2026-09-13-boundary-audit.md) recorded the remaining bind-barrier issue. These observations must not be presented as current host facts without rechecking that repository.

## Recorded verification

- Baseline full suite: **162 passed, 1 failed, 3 skipped in 390.17 seconds**. The failure was R8; its isolated two-variant rerun passed.
- Reproduction script: **9 passed in 24.35 seconds**, covering eight defect classes with two grep cases. Its assertions confirmed defects, so passing did **not** mean correctness acceptance. The final ordinary-text grep probe took 2.957 seconds.
- `ruff check src tests`, `ruff format --check src tests`, and strict Pyright passed.
- The 3,000-file configuration measurement used temporary files/SQLite with processing paused, no network model. Search omission used real Milvus; other models were local deterministic fixtures.
- No StashBase changes, full user journeys, actual cloud-model/OCR/transcription corpus runs, real power failures, or native Windows tests were performed in the initial review. Windows skips required the native platform.

Subsequent regression work closed R1-R8 and the four independent findings. The original script remains historical evidence; maintained tests and [backlog validation](backlog.md) describe the resulting implementation.
